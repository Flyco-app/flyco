## Budget-aware sequencing

The owner requires no paid plans or new charges. Phase 0B is split into local development prerequisites and hosted release prerequisites. Local Auth/Mailpit smoke plus existing quality/database CI permit Phase 1A **local-only** implementation; they do not grant hosted release permission. Private branch protections, independent production environment approval, verified Vercel previews/staging, monitoring and recovery remain open release gates. No gate is claimed enforced, no production workflow is enabled, and the private repo stays private.

The full Supabase profile has unresolved Storage/Realtime/Studio/metadata health failures on this machine. The smaller Auth profile is verified separately and is sufficient for Phase 1A; each later service must pass health/security tests before its owning phase uses it.

## Recommended next task

Once this delivery-controls PR is green, implement Phase 1A locally: request-scoped Supabase SSR clients, a small profile/account-controls migration with grants/RLS, and email verification/login/logout/reset with negative authorization tests and local Mailpit. Keep production deployment, live Stripe, external transactional email and unverified storage/realtime features disabled. This recommendation is not implementation authorization for the current foundation mission.
